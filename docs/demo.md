# 可复现演示

用一个真实、边界清楚的小问题介绍这个 Skill，比承诺节省百分比更可信。

## 演示内容

打开已登录 ChatGPT 的 ego lite，使用 [方案比较任务包](../examples/plan-comparison.md)：8人团队、800元预算，四种协作方案，还有中文、Markdown导出和历史保留约束。

给主 Agent 的话：

> 用 $web-task-relay 帮我省 Agent 额度，按这个任务包比较方案。提交后不用盯页面；我回来时再回收验收结果。

展示三个可验证的动作：启动命令立即返回作业回执；后台程序自己发送、等待并保存结果；回收时核验 B、每月720元和 A/C/D 的排除原因。不要展示账号菜单、侧栏历史、其他任务或本地私密路径。

再展示故障恢复：本地合成网页的测试中，杀死 worker 后会重启观察原页面，服务器仍只收到一次提交。它证明恢复边界，不冒充另一次真实模型任务。

## 可直接改写的介绍

> 写了一个小 Skill：把问题已经讲清楚的方案工作交给网页模型，后台程序等结果，主 Agent 继续干别的。
>
> 只接方案比较和设计分析，写代码、改仓库、调试仍留在主 Agent。默认用 ego lite，已经实测 ChatGPT 自动发送、等待、回收。后台等待不调用模型；崩溃恢复保留截止时间，发送结果不确定时不会自动重发。
>
> 我没测出“节省90%”这样的数字，也不承诺免费额度。当前通用版本把结果保存在本地，下次交互再回收；不会假装一个文件能自动叫醒主 Agent。
>
> 仓库里有完整任务包、验证记录和失败边界。欢迎拿一个定义清楚的问题来试。

发布时链接真实仓库候选和验证记录。演示前确认当前网站能正常使用；网站登录、条款和页面变化仍是外部依赖。持续公开真实问题和有证据的改进，不承诺流量或粉丝结果。

## 更贴近真实工作的调研演示

[企业知识管理任务包](../examples/enterprise-knowledge-research.md)要求比较治理和检索方案，核对一手来源，给出权限/版本边界、贯穿案例和六周试点。它在真实网页首次尝试完成，后台用时约7分39秒。回收后核对9条来源，整理表格并由主Agent发布至用户指定文档系统。网页模型只负责公开资料研究，未获得内部系统访问权或公司文档。

演示可展示任务包、立即返回的回执、后台完成结果和引用核验；录制前隐藏私人侧栏及内部发布地址。把回收后的排版、引用核验与发布成本也计算在内，不宣称后台零模型调用等于整个流程零token。
